# 多 Mac 项目与 Run

项目身份与本机工作目录分开保存。同一账户的 Mac 自动发现并授权彼此，以客户端身份读取对方的加密 Relay。每台 Mac 仍然是其 Run、原生 Session 和工具执行的唯一写入者。

## 数据与迁移

- 本机 schema v9 将现有项目的主目录、附加目录和默认 Agent 移入 `project_local_workspaces`，保留原项目 ID、目录、主目录选择和关联的 Run。`Project.profile` 是组合后的兼容接口；SQLite 中共享的 `profile_json` 不保存执行目录。
- 项目有独立于名称和本机 ID 的账户 UUID。相同名称的两个独立项目不会被自动合并；同步导入的项目保留账户 UUID，并获得本机 ID。
- 共享简介、状态和产品上下文按 `(revision, author)` 确定性合并。修改本机目录不增加共享版本，也不会改变其他 Mac 的目录。过期设置页保存时会拒绝覆盖较新的共享信息。
- 首次导入项目的本机目录为空；用户在项目设置中指定本机主文件夹，并可添加附加文件夹。目录、凭证和实际工具执行仍在执行 Mac。
- 项目归属账户，Peer 缓存、授权引用、游标和发件箱均按账户与空间分隔。退出账户后停止访问 Peer 数据。

## 连接与运行

Account API 允许同账户 Mac 申请另一台 Mac 的设备授权，不能给自己申请，也不能跨账户申请。授权通过已有 P-256 / HKDF / AES-GCM 设备封装交付；Relay Token 和加密密钥只进入凭证库。Peer 的 Relay 角色沿用客户端角色 `ios` 以保持协议兼容，平台记录为 `macos`，不获得目标 Host 的发布或授权权限。

首次建立新设备间的加密授权，需要目标 Mac 在线。授权建立后，可读取 Relay 中已有的加密状态，并在离线时展示缓存。新设备无法在没有任何已授权设备在线的情况下自行恢复加密密钥。

新建 Run 页在有多台 Mac 时显示执行机选择。在线状态来自 Relay presence；离线、无法核验或未配置项目主目录的 Mac 不可选。默认选择本机，已选择的机器离线后不会自动切换执行目标。

创建仅产生草稿。发送、停止、重命名、归档、草稿内容和执行设置均路由回原 Mac；不在调用方创建替代本地 Run。消息、历史分页和附件通过加密通道返回；附件在展示前校验长度与 SHA-256。原生 Session ID 由执行 Mac 持久化并恢复。

WebSocket 提供唤醒和 presence，随后按游标重放事件；后台轮询用于发现机器和连接恢复。发出的命令在本地保存原始 ID 与密文后才提交，重试继续使用同一 ID，目标 Mac 沿用现有持久化命令去重机制。

分页会持续读取到空页后才确认追平；Relay 的 `lastSequence` 只表示当前页的最后事件。历史完成事件被压缩后，重试仍可通过持久化命令回执确认终态。撤销 Mac 时，同时撤销其自有 Relay 空间及访问其他 Mac 的设备授权。

项目目标与 Milestone 随项目同步，定时 Check-in 仍归原执行 Mac，避免每台 Mac 重复执行调度。自动化仍由原 Mac 管理。远程 Git 工作树状态不在调用方计算。

## 发布与验证

iPhone 默认进入账户项目列表，按共享项目 UUID 合并不同 Mac 的副本，并采用最新共享版本。没有共享身份的旧项目按来源分开显示，不按名称误合并。项目详情和 Runs 列表汇总各执行 Mac 的 Run，并标出机器名称和在线状态；创建时明确选择在线且已配置主文件夹的 Mac。

跨账户项目共享另走独立项目密钥和 Account API 权限，不把同账户多 Mac 的 Sync Space 授权交给受邀成员。每台 owner Mac 独立发布其负责的 Chat 来源；既有 Chat 仍回原 Mac 执行，新 Chat 使用所有者指定的执行 Mac。真实多 Mac 加成员账户联调仍是发布门禁，详见 [项目共享计划](project-sharing-plan.md)。

手机为每个同步空间保留独立的 Relay 客户端、缓存、事件游标和 Keychain 授权，自动发现和授权其他 Mac。Run 路由包含来源空间，详情页的消息、历史分页、附件、重命名与归档交给原连接处理。目录与默认 Agent 不在手机上编辑，手机保存共享项目信息时保留执行 Mac 的本地配置。设置中展示设备状态，不再切换全局“当前空间”。首次授权仍要求目标 Mac 在线；已有授权的缓存可离线查看。

先发布 Account API 与 Relay，再升级各 Mac。无需新增云数据库迁移；本机数据库随客户端升级迁移。旧客户端继续本机运行，但不会提供完整的多 Mac 项目身份或新命令能力。

验证包括本机迁移与重开、多目录隔离、并发元数据收敛、账户隔离、加密事件读取、目标机器路由、离线拒绝、客户端权限和原生创建参数。真实双 Mac 验收还需在升级后的服务上完成首次授权、断线恢复和原生 Agent Session 续接；单机模拟测试不代表这些线上步骤已经完成。
